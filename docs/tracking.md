# Tracking — the lead forms, the tags and the CSP

## The lead forms
- Every form asks for a name, a phone number, an email and the space, all four required in the page and by `/api/contact` (400 without them; Michael, 2026-10-05 — until then name + phone were enough, and leads came in with nothing else). → D1 `leads` and a contact row → welcome mail via `_lib/lead-ack.js`. The homepage ballpark's space comes from its chips (a hidden `project`); the picker's options are `SERVICES` in `crm/crm-app.js`. The row is saved before any mail, and a mail failure never loses the lead. Each lead keeps its GA4 client and session ids and the gclid, for the offline conversions (`docs/google-ads.md`).
- After the save the form offers optional details (address, note; email or space only if the form didn't send them) and says a designer will text within one business day to set the visit. **No self-booking since 2026-09-29** (Michael): every CTA → `/#consult`, the request form (`js/main.js` keeps a page with its own `id="consult"` form on that page); the bare `/book/` 301s there (`_middleware.js`), and `/book/?cancel=<token>` only cancels (the link in confirmation and reminder emails). "Text a photo" is an `sms:` link in the mobile bar.
- Anti-spam, all fail-open: Turnstile (the sitekey is in `js/main.js`, the secret is `TURNSTILE_SECRET`; only a token siteverify rejects counts as a bot, and any other siteverify fault is logged and let through), the `hp_url` honeypot (injected by `js/main.js` as `display:none`, never just off-screen, which a browser still autofills; a value that copies the person's own name, email, phone or address is autofill and is not dropped) and the `hp_ms` time-trap. A bot drop answers 200 `{ok:true}` and is kept in D1 `lead_drops` with its reason (`/api/contact`, `/api/lead`; never emailed, never in `leads`): "200 means received, `success:true` means saved" — the client once fired GA4/Ads/Meta on bot drops, so the tags fire on `success:true` only.

## The CSP
- `_headers` (`/*`) allows Google's hosts for the Google tag and the Ads tag (developers.google.com/tag-platform/security/guides/csp), the bare `analytics.google.com`, `ad.doubleclick.net` and `stats.g.doubleclick.net` included, plus Turnstile, Stripe, the Meta pixel and Cloudflare's beacon. `connect-src` still lists `https://purelymail.com`, a leftover of the old mail host.
- The previews in `.claude/launch.json` are `python3 -m http.server`: `nationalcloset` on 4117 over the repo root, and `nationalcloset-dist` on 4118 over `dist/`, which is what deploys. Only `dist/` has each page's FAQPage and the sitemap's dates (`docs/content.md` → The FAQs). Neither sends `_headers` or runs functions, so a CSP change needs `dist/` served with its headers. A preview deployment has the functions, but it shares the live D1 (`DB` is bound to both environments), so a form sent there is a real lead. For the CRM and the functions without the live D1, `nationalcloset-local-crm` on 4119 is `wrangler pages dev dist` over a local D1 in `.wrangler/local-crm` (gitignored; first used 2026-10-06). Load the schema with `npx wrangler d1 export nationalcloset-crm --remote --no-data --output=<file>`, then `d1 execute --local --persist-to .wrangler/local-crm --file=<file>`. Seed a user, a session row and a test job, then sign in with the `ss_session` cookie. Stripe, mail and Turnstile aren't configured there, so the pay page answers "Payments not configured".

## The privacy page
- `/privacy` (2026-09-27) says what the forms, the lead row, the mail, the tags, the edge log and the browser storage do. It is built by `tools/site-build/stage5_privacy.py`, whose docstring names the code behind each paragraph. A change to any of them (a new tag, a new field, the ads running again, `ncc_attr`) changes the script, then rerun it and deploy. The footer link is part of `stage4.py`'s sweep.
